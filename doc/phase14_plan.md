# Phase 14: 對外開放測試準備與編輯器優化 (Completed)

為了在您的自架伺服器 (NUC) 上對朋友們開放測試，我們成功將單機版架構升級為「支援多人連線與資料保護」的伺服器版，並深度優化了和弦編輯器。

## 已完成的開發項目 (Completed Changes)

### 1. 邀請碼註冊與登入機制 (Auth)
- **`frontend/login.html`**: 新增玻璃擬物風格的登入/註冊頁面。
- **邀請碼防護**: 系統預設的邀請碼為 `LiveChordAlpha`。
  
  **🛠️ 如何修改為專屬密語？**
  如果您想要更換邀請碼，請直接在您的伺服器 (NUC) 的 `W:\data\` 目錄底下（或是原始碼對應的 `backend/data/` 內），手動新增一個 `config.json` 檔案，裡面寫入：
  ```json
  {
    "invite_code": "您的專屬神祕密碼"
  }
  ```
  存檔後，新密碼立刻生效！另外，`data/config.json` 已經加入 `.gitignore` 保護，所以不用擔心您的密語會在 Git 同步時外洩。

- 完善的路由保護，所有頁面包含 `/admin` 與背景掃描 API (`/api/auto/start`) 皆受登入身分與權限保護。

### 2. 多使用者資料隔離設計與 Admin 管理員
- **資料隔離**: 將 `favorites.json`、`recent.json` 以及人工修正樂句 `human_sections` 改由 `data/users/<username>/` 資料夾獨立存放，實現每位使用者的資料互不干擾。
- **管理員特權 (Admin)**: 在資料庫建立時，**第一位註冊的使用者**將自動被賦予最高權限 (`is_admin=1`)。首頁會對管理員解鎖「管理後台」按鈕，並獲得自動轉檔背景工作器的操作權限。

### 3. 個人標註資料匯出與備份 (Data Export)
- **一鍵備份**: 在首頁導覽列新增匯出按鈕，一鍵從 `/api/export-data` 下載個人資料庫打包 (`.zip`)，包含播放清單及所有手動調整過的 Ground Truth 標準答案。

### 4. 和弦編輯器極限優化
- **顯微鏡縮放 (Zoom)**: 時間軸最大縮放放大至 150，並支援 localStorage 持久化記憶，換歌免重拉。
- **倒退與快進**: 支援畫面按鈕及鍵盤 `←` / `→` 進行 5 秒跳轉，並克服了暫停時畫面不同步的問題。
- **新增進階和弦面板**: 增補了 `aug`, `dim`, `sus2`, `sus4`, `m7b5`, `maj9` 等常用調色盤按鈕。
- **網格貼齊 (Snap to 0.25s)**: 解除 30px 長度封印，並實作打勾啟用的網格吸附功能，一鍵精準對齊音樂節拍。

## 注意事項與已解決的關鍵 Bug (Gotchas)

在近期的大規模（5 萬首）音樂庫壓力測試與多磁碟 (`@N/` 前綴) 架構下，我們排除了幾個嚴重的系統瓶頸與顯示異常，開發者後續維護請特別留意：

### 1. 效能陷阱：AI 模型讀取與路徑雜湊 (Path Hashing Mismatch)
- **踩坑紀錄：** 當系統引入 `@1/`, `@2/` 等多磁碟前綴時，`chord_api.py` 有過濾掉前綴，但是產生伴奏的 `ai_api.py` 仍使用純手動的 `hashlib.md5()` 處理字串。
- **後果：** 算出的 Hash 鍵值對不上，導致 `/data/chords/` 明明有和弦檔，伴奏生成時仍誤判為 `{"error": "no chord data"}`，連帶造成前端的瀑布流佈局崩潰。
- **解決方案：** 後端全面統一呼叫 `chord_cache.py` 裡的 `song_hash(path)` 函式，確保所有模組對同一首實體檔案都能穩定得到相同的 Hash。

### 2. 網頁播放卡死：同步攔截導致全域鎖定 (Audio Decoding Blocking)
- **踩坑紀錄：** 早期播放器為了等待即時萃取旋律 (`librosa`)，直接把 `audio.pause()` 卡在讀取首發區塊。
- **後果：** 面對龐大音檔或第一次串流計算時，主線程會長時間停止 (甚至超時斷流)，這在 NAS 遠端串流環境下是無法接受的。
- **解決方案：** 放棄攔截播放流程，把 AI 計算搬移到背景處理 (`_loadMelody` 非同步拋出後繼續播放)。即使伴奏尚未產出，依然可以利用已有的和弦生成基礎方塊，實作了「**優雅降級 (Fallback)**」，保證使用者不管網路多慢都能秒播音樂並看到基礎畫面。

### 3. 資料異常與顯示：Batch 標籤未適配 CSS (Source Badge Unmapped)
- **踩坑紀錄：** 批次產生大量曲目時，底層使用 `source: "btc_batch"` 作為來源註記，然而前端舊有的樣式表 (`player.css`) 僅對 `midi`, `chordify`, `btc` 賦予顏色。
- **後果：** 由於 `font-size: 0` 的設計，無顏色對應的標籤 `src-btc_batch` 失去了 `::before` 的色塊，導致介面上的「和弦品質燈號」完全隱形。
- **解決方案：** 在 `player.js` 將不可預期的批次標籤 (如 `btc_batch` 或 `chordy`) 在前端動態正規化為 `"btc"`，重新點亮橘燈；並順勢加入了 `title` 懸停顯示，讓使用者可以直接在燈號上看見 `AI 信心評分 (Quality Score)`。
