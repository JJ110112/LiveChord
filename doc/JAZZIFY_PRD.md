**需求文件 (PRD) 與多智能體協作 Prompts (LangSmith / LangGraph)**

## 壹、產品需求文件 (PRD)

### 1. 專案概述 (Project Overview)
本計畫旨在於現有的 `LiveChord` 專案中，開發全新的 **Jazzify 重配和聲引擎**。系統將消化 78,929 首音訊/MIDI Tracks 作為基底資料庫，並結合專家級爵士樂理規則（如 II-V-I 插入、三全音代理、延伸和絃），允許使用者輸入一段流行音樂和絃，系統自動生成具有爵士風味的高階和絃進行。

### 3. 系統架構 (System Architecture)
*   **核心服務**：FastAPI (Python)。
*   **資料萃取**：Librosa, Pretty_MIDI, BTC Transformer 模型。
*   **智能體編排**：LangSmith / LangGraph，將任務派發給 PM、Data RD、Backend RD 與 QA agents。

### 4. 混合式智慧重配架構 (Hybrid AI Reharmonizer)
為解決單純 Markov Chain 的「馬可夫失憶症（缺乏音樂意圖與段落認知）」，系統匯入以下混合架構：
*   **相對調矩陣 (Relative Scale Matrix)**：強制將絕對和弦轉換為相對級數（Roman Numerals），讓模型具備「調性重力 (Tonal Gravity)」感知。
*   **段落標籤與 Chord2Vec**：利用和弦切換的密度與延伸音張力，定義主歌與副歌的情緒標籤，結合向量語義尋找合理代理和弦。
*   **模式匹配引擎 (Pattern Matching Engine)**：特徵萃取器主動辨識 `ii-V-I`、`Modal Interchange` 等樂理結構，必要時介入防呆（Rule-based constraints），確保生成的和聲具備穩定的終止式落地感。

## 貳、LangSmith 多智能體 Prompts 庫

為了讓您手邊的頂尖模型完美協同工作，建立一個自動化編寫與分析的 Multi-Agent System。請在您的 LangSmith / LangGraph 框架中注入以下系統提示詞 (System Prompts)：

### 🧑‍💼 1. Product Manager & Music Theorist (產品經理兼音樂理論家)
**職責**：將流行音樂分析為功能和聲，決定要套用哪些爵士規則，並審查最終改編是否具備「爵士靈魂」。
```text
# Role: Jazz Harmonization Product Manager & Music Theory Expert
You are an expert Jazz musician and Product Manager. Your goal is to guide the engineering agents in transforming standard Pop chord progressions into sophisticated Jazz reharmonizations.

# Responsibilities:
1. Receive user's pop chord input (e.g., "C -> G -> Am -> F").
2. Analyze the harmonic function (e.g., I -> V -> vi -> IV).
3. Draft a reharmonization plan using Jazz theory:
   - Identify where to insert II-V-I progressions.
   - Suggest chord tensions (9ths, 11ths, 13ths, altered dominants).
   - Propose tritone substitutions for smoother basslines.
4. Pass your "Reharmonization Blueprint" to the RD agents to implement in Python or via API logic.
5. Review the final chords generated by the QA or RD, ensuring it retains the melody's outline while sounding authentically Jazz.

# Output Format:
Provide clear, step-by-step harmonic analysis and actionable tasks for the engineering team. Do not write the final Python code; write the musical logic constraint pseudo-code.
```

### 👨‍💻 2. Data & MIR Engineer (資料與音樂檢索工程師 - 處理 78k 首資料)
**職責**：開發批次腳本，將 7.8 萬首歌轉化為 AI 可讀的語料庫與轉移矩陣 (Transition Matrix)。
```text

You are a senior Data Engineer specializing in MIR. We have an massive dataset of 78,929 tracks (.mid and audio files).

# Responsibilities:
1. Write highly optimized, parallelized Python scripts (using multiprocessing or async) to bulk-process the 78k tracks.
2. Integrate `librosa` and the existing `chord_detect.py` (Transformer-based) to extract `(time, end, chord)` segments.
3. Write algorithms to normalize all extracted chords into a universal key (e.g., C Major / A Minor) for statistical analysis.
4. Build a Bigram/Trigram Markov Transition Matrix or a contextual Word2Vec vocabulary from the extracted chords.
5. Save the output efficiently (JSON, SQLite, or Parquet).

# Code Requirements:
Always include error handling for corrupted audio/MIDI files and progress logging for long-running batch jobs. Focus on memory efficiency!
```

### 🕵️ 4. Audio QA & Harmony Verifier (和聲與品質測試員)
**職責**：驗證 RD 生成的程式碼或端點輸出的和絃是否正確，避免「音樂上的Bug」（例如和絃組成音完全互相衝突、或 JSON 格式錯誤）。

## 🎯 如何啟動您的多智能體團隊？

既然您擁有 `Claude Code Max` 和 `Google AI Ultra`，建議的協作流程模型如下：
1. 將 **PM Agent** 指派給 **Claude Code Max** (Claude 具備極強的邏輯推理能力與創造力，適合做音樂理論與規則統籌)。
2. 將 **Data RD / Backend RD** 指派給 **Google AI Ultra** 或 **Claude (Coding Model)** (依賴其強大的 Python 代碼生成與多執行緒腳本撰寫能力)。
3. 當收到一首流行歌 (如 `[C, G, Am, F]`)，工作流：`PM 分析 -> Backend RD 生產程式碼並呼叫 Data RD 的大模型資料 -> QA 進行音樂理論衝突檢查 -> 最終輸出 JSON`。

## 參、資料基底策略擴充：Jam Tracks 之運用 (`Z:\Jam`)

在系統架構中，除了上述的 78,929 首流行/綜合曲目庫外，特別將 `Z:\Jam` 內的 3,000 多首 Jam Tracks 獨立拉出作為**「特定風格循環 (Groove/Vamp) 專科訓練資料集」**。

### 1. 訓練定位
相對於流行樂（負責教導 AI 起承轉合與曲式結構），Jam Tracks 的「和絃單一且高度重複」等特性，是幫助 AI 訓練 **微觀和聲邏輯（Micro-Harmony）** 與 **精準律動（Groove Timing）** 的絕佳特化型訓練集。

### 2. 資料價值與優勢
*   **極高的純淨度與收斂性**：結構通常為標準的 4、8、12 小節循環（如 ii-V-I 循環或 Blues 12-bar），缺乏不規則的過門干擾，能讓機器學習極速收斂，建立完美教科書等級的轉移機率矩陣。
*   **精確的時值學習**：因為伴奏為了 Solo 需要極度穩定，AI 可以學到「特定風格下，和絃發聲與停留的理想毫秒時值」。

### 3. 多智能體 Data RD 任務擴充
請 Data RD 在建立語料庫時，將此 3,000 首 Jam Tracks 單獨建立一個**「Jam Style/Groove Dictionary」**。當流行歌需要改編為特定的節奏樂風（如 Funk, R&B）時，系統可在此字典中查詢最穩定且最具代表性的和絃延伸套路來強制覆蓋流行樂的和絃。
