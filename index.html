專案總覽

LiveChord 是個人 + 公眾共構的吉他／鋼琴／烏克麗麗 AI 教學工具。 使用者上傳音檔 → BTC Transformer 偵測和弦 + beat_this 偵測節拍 + section detector 分段 → 前端以瀑布流和弦條、88 鍵 / 吉他指板 / 手風琴等多視圖同步播放。 Beta 期 2026-04-16 → 2026-04-26 已結束；目前 NUC 跑個人版（LAN 8800），VPS Hetzner 跑公眾版（livechord.org）。

後端 backend/

FastAPI + uvicorn。main:app 為單一進入點。BTC 和弦偵測跑 ProcessPoolExecutor 隔離 GIL；批次運算用 ThreadPoolExecutor + Semaphore 控 GPU。

前端 frontend/

純 vanilla JS + HTML + CSS（無框架）。Jetpack Compose 否認，這是純 web。player.html + js/player.js 是核心，OSMDroid 不存在於此專案。

批次工具 scripts/

訓練、評測、品質審計、demo 建置等 Python 腳本。從 .bat 啟動以對應到正確環境的 Python venv。

研發工具 tools/

Chordify OCR 對拍、async handler lint、健康監控（Telegram 警報）、capture／screenshot helper。屬於非生產但長存的小工具。

運行資料 data/

和弦 JSON（分桶 data/chords/{hash[:2]}/）、伴奏快取、SQLite DB、模型權重、cover art、demo 音檔。多數子路徑 gitignored。

佈署 deploy/

VPS systemd unit (livechord.service) + Cloudflare Tunnel 設定（cloudflared.yml）。NUC 用 install-service.bat，不在這。

批次檔 40 個

健康監控（已排程跑）

NUC + VPS tools/health_monitor/

每小時透過 Windows Task Scheduler 跑 run-once.bat → check.py 探測 NUC 8800 + livechord.org。Tier 1 純規則（HTTP + log tail），Tier 2 才丟 Ollama hermes3:8b 摘要，超門檻才推 Telegram（chat 8422763333）。Token 自動從 ~/.claude/channels/telegram/.env 讀。
README · config.json · check.py · state.json (cooldown fingerprint)
常用命令 — disable / enable / 測試 / 強制 alert
情境命令 / 步驟
暫停（NUC 停機跑批次時） schtasks /Change /TN "LiveChord-Health-Monitor" /DISABLE
恢復 schtasks /Change /TN "LiveChord-Health-Monitor" /ENABLE
建議先 del C:\Users\hitea\Claude\LiveChord\tools\health_monitor\state.json 清 cooldown 指紋
查目前狀態 / 下次執行時間 schtasks /Query /TN "LiveChord-Health-Monitor" /FO LIST | findstr "Status Next"
手動跑一次（不送 TG） cd tools\health_monitor && python check.py --target both --dry-run
手動跑一次（會送 TG） cd tools\health_monitor && python check.py --target both
強制觸發一次 alert 驗證推送管道 del tools\health_monitor\state.json
cd tools\health_monitor && python check.py --target nuc --inject-error
看最近一次跑的結果 type tools\health_monitor\run.log（rolling 1MB×2，較新的在末段）
調整門檻 / quiet hours / 切換模型 編 tools/health_monitor/config.json（無須重啟，下次 tick 生效）
整條任務移除 schtasks /Delete /TN "LiveChord-Health-Monitor" /F — 重新註冊見 README quick start §7

觸發條件（任一 fire Tier 2）：liveness fail / traceback ≥ 1 / error_count ≥ 3 / last_error_age < 5min / 5xx_count ≥ 1。
Cooldown 30 min by SHA256(last-error-line) — 同一 bug flap 不會狂 ping。
Quiet hours 預設 23:00–08:00 Asia/Taipei；severity=critical 仍會穿透。

MIDI 反向識別 / Chroma 索引

PC build_chroma_index.py

為 LiveChord Phase 4 反向識別建 chroma CQT 索引。Restart-safe + RAM-bounded；資料丟到 AppData/Local/Temp（data/tmp 會被 Defender 誤刪 .py）。輸出 V:/Database/Chroma_Index/。

PC build_tempo_cache.py

為 manifest.jsonl 中每筆建 tempo_cache.json = {hash: BPM}，給 identify_midi.py tempo gate 用。Z:\ 上 22k 檔約 9 小時。Resume-safe。

PC identify_midi.py

用 chroma 索引 + DTW 把不知名 MIDI 反查回 artist/title。Pipeline：artist gate → chroma DTW → tempo 檢驗。

PC chroma_feat.py

索引建立端與 query 端共用的 chroma-CQT 特徵抽取，確保兩邊參數一致（否則 DTW 距離無意義）。

PC analyze_dryrun.py

分析 identify_midi.py --dry-run 產出的 midi_catalog.jsonl：normalized_cost / warp_r2 直方圖 + 「fail 但其實是真陽性」候選排名。

PC midi_to_lab.py

MIDI → .lab 和弦 + 時間軸轉換。

CI / Lint

PC+NUC lint_async_handlers.py + async_handler_baseline.txt

抓沒 await 的 FastAPI async def handler — 過去咬了三次（/api/ai/evaluate、/api/ai/retrain、/api/ai/sections），這些 async def 在 event loop 上跑同步重活。Baseline 已收 62 個既存違規，CI 只擋新增的。提交後端前要跑。
